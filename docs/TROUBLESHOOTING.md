# Troubleshooting

**The page works locally but not on another PC.** Confirm the server is listening on `0.0.0.0:8765` (Windows: `netstat -ano | findstr :8765`). From the other PC, try `Test-NetConnection <SERVER-IP> -Port 8765`. Check the Windows network profile, inbound firewall rule, and any UniFi VLAN isolation. No WAN port-forwarding is needed.

**I cannot find Settings.** Administration is available on the host through `http://127.0.0.1:8765`. A remote browser receives gallery-only access unless its actual client IP is on the explicitly configured VPN admin allowlist and the user has completed both the gallery and separate admin logins. Never forward the port from the public Internet.

**Plex asks for a PIN after opening a title.** Plex Web manages its own browser session and PIN, independent of Cast Explorer. Open local Plex directly, sign in, and configure Plex's own auto-sign-in behavior on trusted browsers only.

**Plex actors have names but no photographs after sync.** Sync now fetches and caches any `Role.thumb` URLs that Plex returns, including for previously indexed movies/shows. Run Sync again to backfill the local `plex-portraits/` cache. If a Role has no `thumb`, but exposes a valid Plex person `Role.key` or `Role.ratingKey`, Plex Cast Explorer will also check that person's Plex metadata for a portrait. Custom metadata agents may provide `metadata://` or `media://` image references, which are accessed through the authenticated Plex metadata-file endpoint. If neither the Role nor the Plex person record exposes an image, use TMDB/TPDB enrichment or add artwork to Plex. Run a **full metadata sync** once when upgrading an existing database if you need to discover previously unindexed person keys; subsequent incremental syncs backfill cached images. Cast images from custom metadata agents (e.g., THDB) are supported when Plex exposes the image in `Role.thumb` or a linked Plex person record: Plex Cast Explorer retrieves Plex-relative images directly and attempts to retrieve public HTTPS custom-scraper URLs through Plex's authenticated `/photo/:/transcode` endpoint. Plex images from private/LAN addresses or unsupported URL schemes are deliberately not proxied (the underlying Plex server may reject them too). For a privately hosted scraper, configure the scraper so Plex supplies a working local Plex image reference or an accessible public HTTPS portrait URL. The app never accepts arbitrary browser-entered image-proxy URLs. If the Plex artwork host is unreachable, Sync finishes with warnings and retries the missing thumbnails on your next Sync. Ensure the server can reach Plex's artwork hosts and that LocalService can write to `C:\ProgramData\PlexCastExplorer\plex-portraits`. A user-approved artwork override is never replaced by this cache.

**Portrait caching shows an HTTP error.** The sync banner now reports the numeric status and updates failures while the scan is running. HTTP **404/410** indicates the image reference is unavailable on Plex and is counted as *missing* rather than a fatal sync error. HTTP **401/403** indicates Plex denied the image request (inspect Plex token and agent/image access). HTTP **429** indicates rate limiting; wait before retrying. HTTP **500–599** indicates an upstream/server issue. For HTTP 401/403/429/5xx, the image pass stops after its current small batch so a large library does not hammer Plex. Already downloaded portraits remain cached and later syncs retry failures. The UI shows **portraits** rather than titles during artwork caching. Logs intentionally do not contain full artwork URLs or Plex access tokens.

**An actor portrait is missing or wrong.** Check the performer and associated Plex credits, try optional provider search, and review the image source. One matching production does not prove a person's identity. You can reject candidates or remove overrides.

**Provider lookups fail.** Verify provider credentials, HTTP errors, API quotas and DNS. Pause enrichment during outages; use Retry failed lookups afterward.

**New version doesn't appear.** Pull `dev` through GitHub Desktop, run `BUILD-INSTALLER.cmd`, and run the resulting uniquely named Setup EXE as Administrator. Setup stops and restarts the Windows service, retains `ProgramData`, and checks the HTTP version before Finish. If Setup fails, inspect `C:\ProgramData\PlexCastExplorer\logs\installer-last-error.txt` and the service wrapper log; do not delete your database or credentials.

## Artwork enrichment reports “Unterminated string” at byte 1,000,000

Older builds read only 1,000,001 bytes of provider JSON, which could truncate large ThePornDB scene-credit responses. The 1.0 release candidate now allows bounded complete JSON responses up to **8 MiB**, with a clear size error for larger responses. Pull and build the updated release candidate, then **pause the enrichment run** before selecting **Retry failed lookups** and **Start / resume enrichment**. Retrying clears only saved error records; previously accepted portraits and unmatched results are retained. If the provider still exceeds 8 MiB, inspect the warning and report it without exposing API tokens or private Plex metadata. Do not disable provider response bounds.
